# NPC 智能仿真与涌现式叙事架构

> 状态：概念设计（Concept）
> 版本：0.1
> 更新日期：2026-11-26
> 范围：NPC 生命周期、专家系统与 LLM Agent 混合智能、玩家关联度调度、动态剧情
>
> 本文记录项目当前已经讨论并认可的设计方向。它是架构基线，不代表所有模块已经实现，也不预设具体引擎、模型或硬件配置。

## 1. 设计愿景

项目目标是构建一个具有赛博朋克氛围的硬核生存仿真世界。世界不应只是围绕玩家运转的任务舞台，而应当在玩家不关注、甚至不在场时持续演化。

NPC 是世界中的独立参与者：拥有身份、客观状态、需求、资源、知识、记忆、社会关系和目标。玩家只是这个社会中的一员，不享有让世界无条件围绕自己运转的特权。

核心原则：

1. **世界持续运行**：玩家不在场时，NPC 的生活、经济、关系和事件仍会推进。
2. **个体持续存在**：普通 NPC 不因不使用 LLM 而失去独立身份、状态、历史或社会关系。
3. **智能与数量解耦**：NPC 总量不等于同时运行的 LLM Agent 数量。
4. **按需分配认知算力**：无关路人采用低频专家系统/规则仿真；与玩家密切相关或处于重要事件中的角色才激活高质量 LLM 推理。
5. **世界规则具有最终权威**：LLM 提出意图和计划，仿真内核验证并执行；模型不能凭空创造资源或直接篡改客观状态。
6. **剧情提供方向而非逐步强制**：编剧设定故事意图、角色目标和必要事实，NPC 可以偏离预定路径，但会在合理条件下持续倾向于追求其剧情目标。

## 2. 总体分层

建议将系统划分为三个相互独立、通过状态和事件交互的层次：

### 2.1 World Simulation（世界仿真）

负责客观世界及确定性规则：

- 游戏时间、天气、环境与区域状态。
- 物理、移动、空间关系和感知事实。
- 物品、库存、货币、资源供需和经济结算。
- 工作、住所、交通、服务设施及其容量。
- NPC 身体状态、生存需求和生命周期。
- 对行动请求进行规则校验，并以事务方式提交世界状态变化。

### 2.2 NPC Intelligence（NPC 智能）

负责 NPC 如何理解世界并选择行动：

- Expert NPC Runtime：规则、状态机、效用/成本评估和批量决策。
- LLM Agent Runtime：上下文检索、记忆理解、复杂推理、计划和自然语言交互。
- Intelligence Manager / Scheduler：判断何时使用哪种执行方式，分配推理预算。

### 2.3 Narrative System（叙事系统）

负责故事意图和剧情目标：

- 保存编剧定义的主题、角色背景、关系、剧情目标和约束。
- 评估剧情目标的进展、停滞、完成或失效。
- 观察世界事件，识别可发展的故事机会。
- 必要时提供合理的机会、信息或事件入口，但不直接控制 NPC 思想，也不绕过世界规则强制结果。

这三个层次不应合并成一个“万能 AI”。世界仿真决定事实，NPC 智能决定角色如何应对，叙事系统提供故事方向。

## 3. 统一 NPC 数据模型

普通 NPC 和 LLM NPC 必须共享同一份权威数据模型。切换智能运行模式只改变决策执行器，不改变 NPC 的身份和世界状态。

建议的逻辑结构：

- **Identity**：稳定身份、背景、性格倾向、职业和个人特征。
- **PhysicalState**：位置、身体状态、健康、伤病、疲劳等。
- **Needs**：食物、饮水、休息、安全、社交等需求。
- **Inventory & Assets**：随身物品、财产、住所、货币和资源。
- **Knowledge**：已知事实、未知信息、信息来源、置信度及可能的错误认知。
- **Memory**：个人经历、事件记忆、重要性、时间、来源和摘要。
- **Relationships**：家庭、朋友、熟人、雇佣、交易、敌对、信任和债务等关系。
- **Goals**：生存目标、短期目标、长期目标及优先级。
- **History**：重要行动、经历和状态变化形成的可追溯时间线。
- **NarrativeBindings**：与剧情角色、剧情目标、故事线的关联。
- **IntelligenceMode**：当前执行模式、激活原因、优先级和调度状态。

数据应区分持久化事实、可推导状态、短期缓存和 LLM 上下文。不要把完整 NPC 状态永久塞进模型上下文窗口；应按任务检索所需信息，并把重要的新经历写回结构化记忆。

## 4. 双运行时：专家系统与 LLM Agent

### 4.1 Expert NPC Runtime（普通 NPC）

无关路人和背景人口默认使用专家系统/确定性仿真，不调用独立 LLM 推理。

适用行为：

- 基础需求变化与生活节律。
- 工作、休息、消费和常规移动。
- 基于规则、状态机、目标选择和成本评估的行为。
- 常规交易、资源消耗和生命周期推进。
- 低频批量模拟，以及重要事件触发的局部更新。

专家系统不是“没有智能”，而是用可解释、可预测、低成本的决策算法处理常见问题。可借鉴城市建造/城市模拟游戏中市民的生命周期、目的地选择、需求和交通成本评估等多智能体仿真思路。

### 4.2 LLM Agent Runtime（关键 NPC）

关键角色、与玩家有持续关系的角色、复杂事件参与者，以及正在进行高价值互动的 NPC，可以激活 LLM Agent。

LLM 适合处理：

- 含糊或复杂情境的理解。
- 多条记忆之间的关联与解释。
- 社会关系、信任、动机和利益冲突的判断。
- 非预设情境下的计划制定和计划修订。
- 复杂协商、对话和社会互动。
- 长期目标之间的权衡。

LLM 输出应采用结构化行动意图/计划，而不是直接执行引擎操作。行动执行器负责检查前置条件、权限、资源、时间、空间和规则约束。

### 4.3 两种运行时共享世界规则

建议采用统一行动协议：

1. Agent 接收经过筛选的感知事实和个人上下文。
2. Agent 提交行动意图或计划（例如寻找工作、购买食物、询问某人、离开危险区域）。
3. World Simulation 校验行动合法性和当前可执行性。
4. 仿真内核执行或拒绝行动，并产生结果事件。
5. NPC 根据结果更新状态、知识、记忆和目标。

LLM 不能直接修改库存、账户、生命状态、位置或其他 NPC 数据。所有变化都必须经由世界仿真规则提交。

## 5. Intelligence Manager：动态智能调度

建立独立的 NPC Intelligence Manager / Scheduler，统一管理所有 NPC 的执行模式和推理预算。

### 5.1 激活依据

不应只按玩家距离判断。调度应综合：

- **Proximity & Perception**：空间距离、视线、听觉及实际感知能力。
- **Relationship**：NPC 与玩家的关系、历史交互和利益关联。
- **Event Importance**：当前事件对 NPC、玩家或世界的影响。
- **Interaction State**：是否正在交谈、交易、合作、冲突或共同执行任务。
- **Narrative Relevance**：是否是关键剧情角色、目标参与者或关键事件见证者。
- **Urgency**：行动是否有时限，延迟推理是否会改变结果。

这些因素形成动态优先级，而不是将距离作为唯一开关。

### 5.2 运行模式

可采用以下逻辑档位（名称和阈值可在实现阶段调整）：

- **Expert / Background**：默认模式。低频、批量、规则驱动；保留独立状态和历史。
- **Expert / Local**：处于玩家附近或区域事件中，但没有复杂互动；提高感知和规则更新频率，必要时触发轻量决策。
- **LLM / Relevant**：与玩家有重要关系、参与关键事件或需要复杂判断；加载相关个人上下文并进行异步推理。
- **LLM / Interactive**：正在进行实时对话、谈判、合作或冲突；获得最高推理优先级和更完整的上下文。

上述档位不是 NPC 的人格或能力等级。同一 NPC 可随事件和关联度升降级。

### 5.3 升级、降级与状态连续性

- NPC 可因玩家接近、交互、关系变化、重大事件或剧情关联而升级。
- NPC 可在交互结束、事件完成或关联度持续降低后降级。
- 使用升级/降级滞后和最短驻留时间，避免在阈值附近频繁切换。
- 降级不能丢失记忆、关系、目标、知识或已发生的经历。
- LLM 激活时按需加载上下文；降级时保存结构化状态和重要记忆，不要求永久保留完整提示词。
- 推理应异步、可取消或可过期；过期结果不得覆盖更新的世界状态。

### 5.4 推理预算与公平调度

- 推理请求进入统一优先级队列，避免每个 NPC 独立占用模型实例。
- 对背景群体采用批量计算；对关键角色采用独立上下文的按需推理。
- 预算不足时，优先保证正在与玩家交互、涉及高风险事件或有紧迫行动窗口的 NPC。
- 对普通角色可回退到专家系统，不能因为 LLM 队列拥堵而停止世界仿真。
- 共享模型权重与推理服务，多份 NPC 上下文彼此隔离。模型大小、并发量和具体硬件不在本阶段固定。

## 6. 批量仿真与独立个体性

批量处理不等于把 NPC 合并成群体平均值，也不等于丢弃个体差异。

即使大量 NPC 都处于 Expert / Background：

- 每个人仍有独立身份、资源、需求、资产、关系和历史。
- 批处理可以共享算法、数据布局和计算过程，但必须产出可归属到每个 NPC 的独立结果。
- 对时间跨度较长、暂时不需要逐步表现的 NPC，可以采用时间推进/区间结算；当 NPC 重新进入重要区域或事件时，再按其个人状态进行补算。
- 资源争夺、库存有限、设施容量、交易顺序等会产生竞争的行为，必须有明确的事务顺序或冲突解决规则，不能让批处理制造重复资源。
- 对有因果影响的事件保留事件记录，确保 NPC 被重新激活时能够正确理解期间发生的事情。

## 7. 生存仿真与社会系统

生存压力应来自资源、时间、风险和选择之间的真实矛盾，而不是单纯加快饥饿条下降。

建议逐步建立以下相互关联的系统：

- 饮食与饮水：获取、储存、购买、烹饪和净化。
- 休息与疲劳：睡眠、工作效率和作息。
- 健康：疾病、受伤、恢复和医疗资源。
- 安全：住所、环境危险、冲突和风险评估。
- 经济：工作、收入、支出、债务、交易和财产。
- 社交：家庭、朋友、信任、合作、冲突和信息传播。
- 心理状态：压力、恐惧、希望、挫折等对决策的影响。

玩家与 NPC 应尽可能遵循相同的客观规则。NPC 不能凭空获得资源，玩家也不能因为是主角而自动获得世界配合。

社会涌现来自个体决策之间的相互作用。例如多个 NPC 争夺有限库存、工作岗位或住所容量，一个人的行动改变其他人的可选方案，进而产生新的计划和冲突。

## 8. 记忆、知识与信息传播

必须区分“世界真实发生的事实”和“某个 NPC 知道的事实”。

- 世界事件写入权威事件记录。
- NPC 只有通过亲历、观察、对话或可信渠道，才能获得相应知识。
- 记忆包含来源、时间、重要性和可信度。
- NPC 可以遗忘细节、误解信息或持有错误认知；但不能无依据地知道玩家在远处做过的事。
- NPC 之间的信息传播应通过实际交流或设定好的传播渠道发生，并考虑延迟、失真和可信度。
- 玩家与 NPC 的交互应更新双方各自的记忆和关系，而不是只在玩家侧保存对话记录。

## 9. 目标约束式动态叙事

剧情不应只是强制执行的任务序列，而应由编剧设定的故事方向与 NPC 自主行动共同演化。

### 9.1 剧本定义方向和约束，不规定唯一过程

编剧可以定义：

- 世界背景、主题和初始条件。
- 角色身份、经历、价值观和初始关系。
- 重要剧情目标及其参与者。
- 必须成立的世界事实或必要前提。
- 期望出现的关键事件、可选事件和可能结局。
- 目标的成功条件、失败条件、期限和代价。

除明确标记为硬约束的事实外，不应把每一步行动写成必须执行的脚本命令。

### 9.2 三类剧情内容

- **Core Facts / Hard Constraints**：世界背景、已经发生的历史事实、角色身份等不可被 Agent 随意改写的内容。
- **Story Goals / Soft Objectives**：角色或故事线希望达成的目标。NPC 会投入资源并倾向于实现，但允许延迟、偏离、失败、替代路径或主动放弃。
- **Emergent Events**：由世界状态和 NPC 行为自然产生的意外事件，不要求事先写入固定剧情树。

### 9.3 剧情目标与 NPC 自主目标

剧情目标应进入 NPC 的目标系统，作为具有来源、优先级、承诺程度、成功条件和失败条件的目标。

所谓 Narrative Commitment（叙事承诺）只影响目标排序、注意力、资源投入和计划倾向，不是强制成功概率，也不能覆盖 NPC 的生存需求、价值观、知识限制或现实条件。

NPC 可以：

- 选择不同路径完成目标。
- 因资源不足、风险过高或关系变化而暂缓目标。
- 因新经历改变对目标的理解。
- 在合理条件下放弃目标，形成失败或替代故事。
- 在偶然事件影响下达成原本未预料的结果。

### 9.4 Narrative Director（剧情导演）

可以建立独立的剧情观察与调度模块，职责是观察而非代替角色行动：

- 跟踪故事线和剧情目标的进展、停滞、完成或失效。
- 发现世界中自然出现的冲突、机会和有意义的角色关系变化。
- 在剧情长期停滞时，选择提供合理机会、线索、信息来源或事件入口。
- 根据实际世界历史记录故事结果，允许不同游戏过程形成不同版本的故事。

Narrative Director 不得直接篡改 NPC 内心状态、强迫 NPC 执行动作、凭空创造物资或绕过世界仿真规则。若要引入新事件，必须作为可验证的世界事件进入仿真，并满足因果和资源条件。

### 9.5 涌现叙事的验收原则

同一份剧本在不同玩家行为和世界随机条件下可以产生不同经历。叙事系统应能解释“发生了什么、为什么发生、哪些角色知道、目标为何完成或失败”，而不是只检查玩家是否按顺序触发预设节点。

## 10. 行动、事件与一致性

建议以事件和行动请求作为子系统边界：

- 感知系统输出带来源和时间戳的感知事实。
- NPC Runtime 输出结构化行动请求。
- World Simulation 校验并提交行动。
- 已提交的状态变化产生权威世界事件。
- 记忆系统和叙事系统订阅相关事件。
- LLM 推理结果应携带其所依据的状态版本/事件时间点；若世界已变化，应重新验证或丢弃过期计划。

关键要求：

1. 不允许 LLM 直接写世界状态。
2. 不允许 NPC 无来源地获取信息。
3. 不允许批量结算产生重复资源或绕过竞争关系。
4. 不允许过期推理结果覆盖新状态。
5. 同一事件的处理应具备去重和幂等能力。
6. 重要行动应记录决策依据、执行结果和因果链，便于调试和回放。

## 11. 推荐的首个垂直切片（Prototype）

不要一开始就制作整座城市或接入大量 LLM。先验证“世界能否在玩家不干预时自行运转”。

建议原型范围：

- 一个小型贫民区或街区。
- 约 20–30 个 NPC。
- 每个 NPC 拥有独立身份、住所/位置、需求、库存、工作状态、关系和记忆。
- 有限的食物、水、货币、工作岗位和商店库存。
- 所有 NPC 默认使用专家系统低频运行。
- 选取少量关键角色接入 LLM Agent。
- 玩家可作为普通居民加入，不享有特殊世界规则。
- 一条有明确目标但允许多路径、延迟或失败的简单剧情线。
- 事件记录、NPC 个人时间线和剧情目标进展可观察。

### 原型验收问题

1. 不控制玩家，NPC 是否仍能连续生活和推进状态？
2. 资源是否守恒，库存竞争和交易是否正确？
3. NPC 是否只知道自己有渠道获得的信息？
4. 将普通 NPC 升级为 LLM Agent 后，是否能保留完整身份、状态、关系和历史？
5. LLM 计划是否经过世界规则验证，而不是直接改变事实？
6. 玩家交互结束后，NPC 降级是否会保留新记忆？
7. NPC 是否可能用不同路径完成剧情目标，也可能合理失败？
8. 世界是否能产生剧本没有逐条预设的事件，并保留可解释的因果记录？

## 12. 当前明确的架构决策与暂不确定事项

### 已明确的设计方向

- 普通无关路人默认采用专家系统，低频执行并支持批量处理。
- 与玩家密切相关、参与重要事件或实时交互的关键角色采用 LLM Agent 进行高质量推理。
- 所有 NPC 共享统一、持久化的个体数据模型；智能模式可以动态升级和降级。
- LLM 负责理解、推理和提出行动意图，世界仿真内核负责校验和执行。
- 剧情脚本定义方向、目标和约束，不要求 NPC 严格按照预设步骤执行。
- NPC 对剧情目标具有倾向性，但允许偏离、失败、改变路径或放弃。
- 叙事系统观察世界并提供合理机会，不应强制操纵 NPC 或破坏客观规则。

### 尚待后续设计

- 具体专家系统算法、行为树/效用系统的组合方式。
- NPC 状态与记忆的精确 Schema、存储和检索方案。
- 玩家关联度、事件重要性和智能等级的具体评分公式及阈值。
- LLM 模型尺寸、推理服务、并发与上下文预算。
- 时间推进、离线补算和批量结算的精确机制。
- 剧情目标 DSL、约束表达、Narrative Director 的具体算法。
- 世界事件总线、事务提交、回放和存档机制。
- 最终引擎、渲染技术和网络/多机部署方案。

以上事项应通过原型和性能测试逐步确定，不在概念阶段过早锁定。
